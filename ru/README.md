# Qwen 3.ocho (C++) — стохастический рендеринг траекторий с циклом решение/коммит на нативном движке инференса CUDA/HIP/ROCm (NVIDIA GB10 + 4x AMD MI50)

Нативное декодирование M=1 на этом устройстве: 27–29 tok/s на производственном рецепте 8K без
спекулятивного декодирования (приёмочные записи замороженных бинарников, раздел 4). Стохастические
режимы Qwen 3.ocho работают рядом с этим путём; их построчная стоимость рендера указана отдельно
и не является заменой нативного пути.

Двухускорительная система резидентного инференса и стохастических вычислений вокруг модели класса
Qwen3.8-Flash-Next. Одна машина несёт уровень из 4x MI50 (gfx906), вторая — уровень NVIDIA GB10.
Уровень AMD владеет префиксом модели, слоем PLE и выходной головой; уровень NVIDIA владеет хвостом
модели. Ни один ускоритель не держит модель целиком.

Этот репозиторий — инженерная запись ночного окна 2026-09-07: линия стохастических вычислений
(новая работа) и линия продуктового декодирования (одно исправление корректности и одна
сохранённая замена селектора). Это кандидат в релиз, производный от канонического
фриз-пакета (`FREEZE_QWEN_OVERNIGHT_20260907/` с SHA256SUMS); пакет — единственный авторитет.
Иерархия авторитета и метки происхождения компонентов — в `freeze/PROVENANCE.md`.

## 1. Что это за репозиторий

Система нативного (неспекулятивного) исполнения модели на CUDA (NVIDIA GB10, sm_121a) и HIP/ROCm (4x AMD MI50, gfx906), плюс GPU-нативный движок
стохастических вычислений, который трактует резидентное причинное состояние модели как
условный оператор перехода. Движок разветвляет одно резидентное родительское состояние в поле
независимых стохастических ветвей, продвигает их на GPU, прореживает и уплотняет, вычисляет
наблюдаемые и сводит всё поле к статистическим величинам — не экспортируя каждую траекторию
в CPU.

Две подсистемы связаны: механизм резидентного состояния, обслуживающий продуктовые запросы
(префилл, доливка, продолжение), — это тот же механизм, который разветвляет стохастическая
линия.

## 4. Что фактически измерено

Нативное декодирование M=1, резидентный промпт 8 038 токенов, 300 сгенерированных токенов,
зафиксированные частоты, замороженные бинарники:

| конфигурация | хвост Spark | слитая голова AMD | tok/s |
|---|---|---|---|
| замороженный продуктовый бинарник (базовая линия) | 23.0 мс/токен | 10.7 мс/токен | 29.70 |
| сохранённые изменения B1+B2 | 23.1 мс/токен | 10.8 мс/токен | 29.44 |

Сохранённые изменения — исправление корректности (B1)
и точная замена селектора (B2); их суммарный сквозной эффект ≈ +0.1 мс/токен, внутри
разброса между запусками. См.
`receipts/B1_CAPTURE_FIX_RECEIPT_20260907.md`, `receipts/B2_RADIX_RECEIPT_20260907.md` и
`docs/LIMITATIONS.md`.

Замороженный префилл (отдельный фриз, в этой работе не менялся): 8 038 токенов за 5.21 с
≈ 1 543 tok/s. Резидентная доливка/инъекция контекста продолжает существующее состояние без
повтора (см. `docs/PREFILL_REFILL.md`).

## 5. Qwen 3.ocho — стохастический рендеринг траекторий с циклом решение/коммит

Продуктовый слой стохастической линии на уровне модели. Одно резидентное родительское состояние
разветвляется на восемь построчных продолжений на обоих ускорителях; строка 0 остаётся жадной,
строки 1–7 сэмплируются детерминированным построчным Gumbel-max шумом (параметризованным сидом).
Восемь строк продвигаются синхронно через M-строчный регионный путь (префикс AMD -> хвост Spark ->
голова AMD).

- **Ocho Beam**: восемь будущих и есть результат. Поле K=16: 5.16 с, 24.8 sibling-tok/s. Beam
  K=1500 (задачи C++/Rust): ~850 с каждый, ~14 sibling-tok/s; на длинных горизонтах строки при
  температуре 1.0 накапливают артефакты хвоста словаря, жадная строка остаётся чистой.
- **Память ветвей (PoC)**: проигравшие ветви отдают по одной классифицированной пропозиции за
  раунд (constraint/failure/unresolved), впрыскиваемой в чемпиона ограниченным блоком
  [OCHO BRANCH MEMORY] через резидентный долив; KV проигравших никогда не объединяется.
- **Ocho Loop**: рендер -> оценка -> выбор -> коммит -> продолжение. Оценка проста и полностью
  логируется (штрафы за ранний конец и артефактные токены, затем расстояние до консенсуса по
  сигнатуре рекуррентного состояния). Полное состояние выбранной строки фиксируется обратно в
  родительский слот на обеих машинах. Прогон возможностей: K=48 x 16 итераций = 768
  зафиксированных токенов непрерывных инженерных рассуждений, ~24 с на цикл, чистый выход;
  гейт идентичности поля в одном буте побитово идентичен.

Второй след возможностей на задаче DAG-планировщика Rust (FREEZE_OCHO_RUST_LOOP_20260907)
повторяет ту же структуру из 16 циклов, выборщик переключается между шестью строками. Сэмплер с
ограниченными кандидатами (чек SAMPLER_TOPK_RECEIPT_20260907) сохранён: 311.9 мс/шаг (было 324.6
при полном словаре), argmax строки 0 по полному словарю побитово идентичен, наблюдаемое текстовое
загрязнение хвостом словаря устранено.

Полный механизм, измеренное поведение, ремонты и ограничения: docs/QWEN_3_OCHO.md. Замороженные
артефакты возможностей: FREEZE_OCHO_20260907, FREEZE_OCHO_CAPABILITY_20260907,
FREEZE_OCHO_RUST_LOOP_20260907, FREEZE_OCHO_TOPKSAMPLER_20260907 (дерево канонического
фриз-пакета; проверены SHA256).

## 6. Стохастический вычислительный движок

```
  резидентное условное состояние
        |
  GPU-нативный форк
        |
  детерминированный счётчиковый ГПСЧ (seed, branch, step, lane)
        |
  продвижение поля Колмогорова (локальное состояние ветви, общая неизменяемая история)
        |
  выживание / прореживание / уплотнение
        |
  вычисление наблюдаемых
        |
  редукция Думитреску (N, Σw, Σw², Σw f, Σw f², log-sum-exp, ESS)
        |
  матожидание / интеграл / распределение / рендер поля
        |
  малый результат хосту
```

Важное различие: одно дорогое резидентное причинное состояние становится начальным условием
GPU-резидентного стохастического поля, чьи траектории вычисляются и редуцируются на GPU. CPU
никогда не итерирует по значениям ветвей. Компоненты (все с чеками; см. `receipts/` и
`docs/STOCHASTIC_ENGINE.md`):

- **ГПСЧ** — Philox4x32-10, счётчиковый, реализован по замороженной спецификации проекта
  (key=(slot,round); counter=(position,branch,purpose,index)). Тест с известным ответом на хосте
  и устройстве.
- **Редукция Думитреску** — проектное имя примитива взвешенной редукции поля. Накопление fp64,
  поблочные частичные суммы, детерминированное слияние на хосте, несколько наблюдаемых на ветвь,
  страж нулевого веса. Проверена против CPU-эталона fp64 на 14 случаях.
- **Продвижение поля Колмогорова** — условный родитель разветвляется на M ветвей; локальное
  изменяемое состояние ветви плюс общая неизменяемая история; пошаговое прореживание монетой
  смерти с весовой компенсацией (несмещённо); уплотнение исключающим сканом; слитное накопление
  наблюдаемых. В синтетическом эксперименте три наблюдаемые с замкнутой формой совпали.
- **Динамическое выживание ветвей** — прореживание и уплотнение выполняются каждый шаг; мёртвые
  ветви дают нулевой вес и удаляются.

Пропускная способность: синтетическое поле держит ≈ 1.6e9 шагов-траекторий/с при M ≥ 262 144
ветвей на GB10 (ниже ~16K ветвей — ограничение запуском). См.
`receipts/THROUGHPUT_LAW_RECEIPT_20260907.md`.

## 7. Интегрирование Монте-Карло

Движок проверен на интегралах с замкнутой формой; выборка, вычисление подынтегральной функции
и редукция — полностью на GPU:

| гейт | аналитика | N | оценка | |ошибка| | время | выборок/с | примечания |
|---|---|---|---|---|---|---|---|---|
| MC-A: E[X²], X~U(0,1) | 1/3 | 1 048 576 | 0.333675 | 3.4e-4 | 1.9 мс | 5.4e8 | без весов |
| MC-A2: через q(x)=2x | 1/3 | 1 048 576 | 0.333907 | 5.7e-4 | 2.1 мс | 5.0e8 | взвешенно, ESS 3.1e5 |
| MC-B: E[Σ X_j²], d=16 | 16/3 | 262 144 | 5.334713 | 1.4e-3 | 0.65 мс | 4.1e8 | векторный ГПСЧ |
| MC-A3: стратификация S=64 | 1/3 | 1 048 576 | 0.333335 | 1.8e-6 | 1.8 мс | 5.8e8 | ≈188x меньше ошибки при равном времени |

Стратифицированный результат — сохранённый механизм снижения дисперсии: примерно в 188 раз
меньше абсолютной ошибки при сравниваемом wall-time, а не «Монте-Карло в 188 раз быстрее».
Для систем такого класса полезная метрика — статистическая работа в секунду (ошибка при
фиксированном времени, ESS, траекторий/с), а не только выборок/с. См. `docs/MONTE_CARLO.md`
и `figures/variance_reduction.svg`.

## 8. Стохастический рендеринг

«Рендеринг» здесь означает визуализацию статистической структуры, порождённой условным
стохастическим процессом, а не обычную растровую графику. Конечные пары состояний синтетического
поля (X_T, X_{T-1}) разбиваются на GPU в сетку плотности 512x512 — выборка, эволюция,
наблюдаемые и редукция на стороне GPU. Сохранённый артефакт:
`figures/kolmo_field_density.ppm` (и lossless-конверсия в PNG).

Подпись: M = 1 048 576 ветвей; T = 64 шага; динамика OU a=0.50, σ=1.00 от родителя x0=1.00;
Philox4x32-10 (seed 42); пошаговая монета смерти p=0.01 с весовой компенсацией 1/(1-p);
наблюдаемая = пара конечных позиций; сетка 512x512 по [-3,3]²; 44.7 мс продвижения; ~1.5e9
шагов-траекторий/с; ESS = 550 847. См. раздел «Рендеринг» в `docs/STOCHASTIC_ENGINE.md`.

## 9. Уровень AMD

Уровень gfx906 — вычислительный участник первого класса. Он держит префикс, PLE и слитую голову
каждого продуктового токена, и именно его оставшиеся миллисекунды — крупнейший измеренный рычаг в пути декодирования. Его ценность — в декомпозиции, а не в изолированных бенчмарках устройства:
аппаратура, проигрывающая в обычных одноустройственных сравнениях, остаётся материально
полезной, когда архитектура назначает ей работу по её физическим характеристикам (пропускная
способность/ёмкость HBM для резидентных слоёв, собственные HIP-ядра, владение состоянием).
Измеренный налог длинного контекста на стороне AMD (≈2.4-2.8 мс/токен при 8K) — крупнейший
одиночный измеряемый рычаг. Две гипотезы об этом налоге проверены и отвергнуты контролируемым
сравнением (HIP-графы: ранний фриз; бисекция селектора: это окно). Остающееся измеренное
место — рост ядра скоринга QSA и flash-внимания. См. `docs/AMD_HETEROGENEOUS.md` и
`figures/latency_breakdown.svg`.

## 10. Методология корректности

Побитовая идентичность не является универсальным требованием; у каждого механизма свой гейт.
Использованы: токенная идентичность там, где семантика обязана быть точной; аналитическое
матожидание для ядер Монте-Карло; тесты с известным ответом для ГПСЧ; CPU-эталон для редукции;
детерминированный повтор по сиду; независимость ветвей; сравнение сигнатур состояния;
причинно-эквивалентное продолжение; compute-sanitizer memcheck; хеш-происхождение. Изменения
вносятся по одному механизму: строгая сборка, минимальный физический гейт, сквозной чек, затем
KEEP / ROLLBACK / PROMOTE. См. `docs/CORRECTNESS.md` и `docs/BUILD_LAW.md`.

## 11. Воспроизведение результатов

```
./scripts/verify_freeze.sh                 # проверка публичных артефактов по SHA256SUMS
./scripts/reproduce_spark_tests.sh         # юнит-тесты ГПСЧ + Думитреску (CUDA)
./scripts/reproduce_mc.sh                  # гейты MC-A / MC-A2 / MC-A3 / MC-B
./scripts/reproduce_stochastic_field.sh    # синтетическое поле + артефакт рендеринга
```

Требования: CUDA ≥ 12 (nvcc); для автономных ядер — GPU ≥ sm_70 (сохранённые сборки нацелены на
sm_121a; скрипты уважают `CUDA_HOME` и `QF_ARCH`). Эксперименты с моделью (MC-C, чеки
декодирования) требуют двухмашинного стенда и замороженных бинарников; методика — в
`docs/REPRODUCIBILITY.md`; только из этого репозитория они не запускаются.

## 12. Известные ограничения

- Точное дерево исходников, породившее замороженный продуктовый бинарник AMD (824e5c50…),
  **не восстановлено**. Пересборки из доступного зеркала (с radix-селектором и без него)
  расходятся с замороженным бинарником на токене 0; сам порт селектора проверен юнит-тестами и
  сохранён как готовый к применению, но не может получить продуктовый интеграционный чек до
  восстановления истинного дерева исходников. См. `freeze/PROVENANCE.md` и
  `docs/LIMITATIONS.md`.
- Стохастическая ширина M>8 не валидирована: при M=16 сигнатуры состояния второго слота имеют
  другой масштаб, а слот 0 дрейфует относительно прогона M=8. M=8 остаётся валидированной
  шириной.
- Регионный протокол передаёт только token id, без построчных логарифмов вероятностей;
  взвешенный Монте-Карло на модели требует расширения протокола.
- Семплер модели сканирует весь словарь (~110 мс/шаг при M=8); семплер по ограниченному
  набору кандидатов — следующий механизм.
- Фильтр артефактов Qwen 3.ocho — пороговый дискриминатор по id на хосте с ложноотрицательными
  ниже id 110000; см. `docs/QWEN_3_OCHO.md`.
