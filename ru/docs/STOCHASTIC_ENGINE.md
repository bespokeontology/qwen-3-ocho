# Стохастический вычислительный движок

## Концепция

Авторегрессионная модель с резидентным причинным состоянием — дорогой условный оператор
перехода. Движок трактует одно резидентное условное состояние как начальное условие
GPU-резидентного стохастического поля: M независимых ветвей разветвляются из него, продвигаются
пошагово, прореживаются, уплотняются, наблюдаются и редуцируются — без экспорта каждой
траектории в CPU. Конвейер:

    резидентное условное состояние -> GPU-форк -> счётчиковый ГПСЧ на ветвь -> продвижение поля
    -> выживание/уплотнение -> вычисление наблюдаемых -> редукция -> малый результат хосту

«Колмогоров» и «Думитреску» — проектные имена двух взаимодополняющих примитивов: Колмогоров
продвигает условное стохастическое поле; Думитреску вычисляет и редуцирует его. Разделение
генерации и редукции намеренно даже там, где ядра слиты.

## Модель состояния ветви

На ветвь: добавляемые KV-строки, рекуррентное состояние GDN, кольца свёрток, пулы индексатора,
позиция, текущий токен, логарифм веса, аккумулятор наблюдаемых, флаг жизни. Общее: неизменяемая
история родителя (потомки только добавляют; родительские строки никогда не переписываются —
доказано чеком независимости форка). Состояние ГПСЧ не хранится вообще: потоки счётчиковые,
адресуются (seed, branch, step, lane). Дескриптор ветви 16 B; 1M ветвей инициализируется за
0.08 мс, копирование-при-записи в текущем масштабе не нужно.

## Компоненты

### ГПСЧ (stoch/include/philox.cuh)

Philox4x32-10 по замороженной спецификации проекта: key=(slot,round);
counter=(position,branch,purpose,index); uniform=(word0>>8)*2^-24. Десять раундов, инкремент
ключа Вейля после каждого раунда кроме последнего. Тест с известным ответом:
counter=key=0 -> 6627e8d5 e169c58d bc57ac4c 9b00dbd8 (хост и устройство). Также проверены:
детерминизм, независимость потоков на 2 048 ячейках, снапшот/восстановление счётчика,
среднее/дисперсия 1M равномерных. Чек: receipts/RNG_RECEIPT_20260907.md.

### Редукция Думитреску (stoch/reduce/dumi.cuh)

Однопроходная взвешенная статистика по полю ветвей: N, Σw, Σw², Σw f_k, Σw f_k², max log-w,
log-sum-exp(log w), ESS = (Σw)²/Σw², для K наблюдаемых на ветвь. Накопление fp64; каждый блок
пишет частичную сумму; хост сливает частичные суммы в double (детерминированно, без
межблочных атомиков). Страж нулевого веса lw <= -1e300. Валидировано против CPU-эталона fp64 на
14 случаях (нечётные размеры, крошечные/огромные/нулевые веса, несколько наблюдаемых). Чек:
receipts/DUMI_RECEIPT_20260907.md.

### Продвижение поля Колмогорова (stoch/field/kolmo_field.cu)

Синтетическое поле: условный родитель x0 разветвляется на M ветвей динамики
Орнштейна-Уленбека x <- a*x + sigma*xi с шумом Бокса-Мюллера из счётчикового ГПСЧ. Каждый шаг:
продвижение, затем монета смерти (p=0.01) прореживает ветвь с весовой компенсацией 1/(1-p)
(несмещённая русская рулетка), затем уплотнение выживших исключающим сканом. Наблюдаемые
накапливаются по шагам и редуцируются один раз в конце. Три гейта с замкнутой формой:
E[X_T] = a^T x0; E[X_T²] = (a^T x0)² + sigma²(1-a^{2T})/(1-a²); E[(1/T) Σ x_t²]. Все три
совпали в пределах ожидаемой ошибки Монте-Карло; выживаемость 52.5% совпала с предсказанием
монеты смерти 0.99^64 = 52.6%. Чек: receipts/KOLMO_FIELD_RECEIPT_20260907.md.

### Поле на модели (MC-C)

Та же механика на резидентной модели: прогретый родитель из 382 токенов (разрез 8/40)
разветвляется на M=8 строк. Строка 0 — жадный контроль; строки 1-7 сэмплируют переходы
температуры 1 по Gumbel-max (серверный семплер, детерминированный splitmix64 с ключом
(seed,row,v)). После 16 шагов сигнатуры состояния каждой строки (sigR = сумма состояния
GDN+свёрток по слоям Spark; sigK = сумма K/V последних 4 записанных позиций) читаются через
аддитивный переключатель QF_M8_FORK_SIG и редуцируются без весов по 7 сэмплированным строкам:
среднее поля sigR +228 против жадной строки sigR -704, выборочное ст.откл. 1076, ESS 7;
распределение конечных токенов 318 x3, 264, 19, 8260, 53235, 156566. Поле выполняется со
скоростью 21.8 токенов-сиблингов/с (367.5 мс/шаг); цикл Гумбеля по всему словарю стоит
~110 мс/шаг и является первой целью оптимизации. Повторный прогон побитово воспроизвёл
траектории токенов (значения сигнатур варьируются в документированной арифметической полосе
M-строк). Чек: receipts/MCC_MODEL_FIELD_RECEIPT_20260907.md.

Интерпретация sigR ограничена: это детерминированный функционал рекуррентного состояния ветви,
используемый как наблюдаемая траектории; более широкая статистическая интерпретация не
заявляется. M>8 не валидировано (см. docs/LIMITATIONS.md).

## Пропускная способность

Синтетическое поле, T=64 шага, GB10, seed 42: 2.6e7 шагов-траекторий/с при M=1 024; 3.8e8 при
16 384; 1.52e9 при 262 144; 1.60e9 при 1 048 576. Ниже ~16K ветвей — ограничение запуском;
выше ~262K — насыщение. Единицы: шаги-траектории/с (M ветвей, каждая на один шаг); это не
завершённые траектории/с и не токенная пропускная способность. Чек:
receipts/THROUGHPUT_LAW_RECEIPT_20260907.md.

## Рендеринг

Рендеринг означает визуализацию статистической структуры условного стохастического процесса.
Конечные пары состояния поля (X_T, X_{T-1}) разбиваются на GPU в сетку плотности 512x512
(по осям -3..3) и записываются как PPM. Параметры: M=1 048 576; T=64; a=0.50, sigma=1.00;
x0=1.00; сид Philox 42; p_kill=0.01 с весовой компенсацией; 44.7 мс продвижения; ~1.5e9
шагов-траекторий/с; ESS 550 847. Артефакт: figures/kolmo_field_density.ppm (+ lossless PNG).
Это демонстрирует общую цепочку — стохастические выборки -> эволюция поля -> наблюдаемые ->
редукция/рендер — а не графический конвейер.
