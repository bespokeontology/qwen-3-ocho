# Архитектура

## Декомпозиция

Модель разрезана между двумя ускорителями. В продуктовой конфигурации уровень AMD владеет слоями
0..15 (префикс), слоем констант PLE и lm_head; уровень NVIDIA владеет слоями 16..47 (хвост) и
QSA-индексатором хвостовых слоёв. Каждый шаг декодирования:

1. AMD-префикс: резидентное состояние префикса продвигается для нового токена; остаток
   отправляется по сети.
2. Хвост Spark: выполняются хвостовые слои (плотные FP8-проекции, маршрутизируемые NVFP4
   эксперты, гиперсвязи, рекуррентность GDN, разреженное внимание QSA где применимо); остаток
   возвращается.
3. Слитая голова AMD: выходные HC, lm_head, argmax; готовится окно следующего префикса.

Таким образом, уровень AMD появляется дважды за токен на критическом пути. Точки разреза
конфигурируемы (QF_LAYER_BEGIN, QF_AMD_PREFIX). См. figures/heterogeneous_pipeline.svg.

## Резидентное состояние

Оба уровня держат всё резидентным: веса, KV-кэши, рекуррентное состояние GDN, кольца свёрток,
пулы QSA-индексатора, карты слотов экспертов. Запрос — не холодная загрузка. Именно это делает
осмысленными доливку (инъекцию без повтора), продолжение и форк; см. docs/PREFILL_REFILL.md.

## Стохастическая надстройка

То же резидентное состояние обслуживает стохастическую линию: одно прогретое родительское
состояние копируется в M слотов строк на обоих уровнях (форк), затем продвигается как поле.
Строки разделяют неизменяемую историю родителя и расходятся только через локальное изменяемое
состояние ветви и независимые потоки ГПСЧ. См. docs/STOCHASTIC_ENGINE.md.

## Точность

Плотные веса — FP8 (E4M3, масштабы по 64 блока); маршрутизируемые эксперты — NVFP4 в
продуктовом пути Spark и INT8 на продуктовом уровне AMD (обе арены в топологии форка);
константы PLE и lm_head — повышенной точности. Изменения точности закрыты ранними фризами и в
эту работу не входили.
