# Qwen 3.ocho (C++) — стохастический рендеринг траекторий с циклом решение/коммит на нативном движке инференса CUDA/HIP/ROCm (NVIDIA GB10 + 4x AMD MI50)

Статус: граница возможностей 2026-09-07. Документ фиксирует работающий механизм, а не результат
бенчмарка. Все числа — измерения на доступном той ночью оборудовании; тепловые/мощностные
ограничения узла указаны там, где они существенны.

Опорная нативная производительность: путь декодирования M=1 на этом оборудовании — один хвост
DGX Spark (GB10) плюс префикс 4x AMD MI50 — даёт 27–29 tok/s на производственном рецепте 8K без
спекулятивного декодирования (измерено по приёмочным прогонам канонического ночного фриза).
Стохастические режимы Qwen 3.ocho работают рядом с этим путём; их построчная стоимость рендера
указана ниже отдельно и не является заменой нативного пути.

## 1. Что это

Qwen 3.Ocho — режим нативного движка (префикс 4x AMD MI50 + хвост NVIDIA GB10,
архитектура описана в ARCHITECTURE.md), который рендерит несколько стохастических продолжений
одного резидентного состояния модели и либо возвращает их как параллельные будущие (Beam), либо
повторно оценивает и фиксирует одно из них в резидентном состоянии (Loop).

Два равноправных режима:

- **Ocho Beam**: одно резидентное родительское состояние разветвляется на восемь альтернативных
  будущих, каждое рендерится независимо заданное число шагов. Будущие и есть результат.
- **Ocho Loop**: рендер восьми будущих -> оценка -> выбор -> коммит выбранного следствия в
  резидентное состояние -> продолжение из этого причинного состояния -> рендер следующих восьми.

## 2. Механизм

Резидентный родитель — состояние M=1 после прайминга промпта: KV [0,P) на обоих ускорителях,
рекуррентные (GDN) состояния, кольца свёрток, пулы индексатора и история PLE. Форк копирует это
состояние в восемь построчных слотов на обеих машинах (префиксные слои AMD и хвостовые слои Spark).
Строка 0 остаётся жадным argmax; строки 1–7 сэмплируются из логитов головы построчным
Gumbel-max шумом, детерминированным при заданном сиде:

    sample_v = argmax_v ( logit_v / T - log(-log(u_v)) ),  u_v = splitmix64(seed ^ (r<<40) ^ v)

где v — индекс словаря. Восемь строк продвигаются синхронно через M-строчный регионный путь
(префикс AMD -> хвост Spark -> голова AMD) шаг за шагом; по сети передаются только id токенов.

Стадия оценки Loop намеренно проста и полностью логируется: строка штрафуется за ранний конец
последовательности и за артефактные токены хвоста словаря (измеренный кластер «кракозябр» при id
токена >= 110000); оставшийся счёт — расстояние сигнатуры рекуррентного состояния строки (sigR:
сумма состояний GDN и свёрток по слоям Spark) от медианы поля. Строка с лучшим
лексикографическим счётом фиксируется: её полное состояние (KV, рекуррентное состояние, пулы
индексатора, история PLE) копируется обратно в родительский слот на обоих ускорителях, и следующая
итерация разветвляется уже из этого состояния. Дерево условных вероятностей сохраняется в журнале
запуска: токены каждой ветви, сигнатуры, счета и каждый выбор.

Инвариант идентичности поля: одно и то же родительское состояние, сид и запрос форка дают одно и
то же восьмистрочное поле независимо от того, что сервер обслуживал ранее. Для этого потребовался
сброс счётчика вызовов сэмплера головы на границе форк/сброс (раздел 4).

## 3. Измеренное поведение

| конфигурация | измерение |
|---|---|
| поле K=16, 8 строк, промпт задачи кодирования | 5.16 с; 322.7 мс/шаг; 24.8 sibling-tok/s (3.10 на строку) |
| Beam K=1500, задача C++ | 851.7 с; 567.8 мс/шаг; 14.1 sibling-tok/s |
| Beam K=1500, задача Rust | 845.6 с; 563.7 мс/шаг; 14.2 sibling-tok/s |
| Ocho Loop, K=48 x 16 итераций, задача C++ | 768 зафиксированных токенов; ~24 с на цикл рендер+коммит; чистый выход |
| Гейт идентичности поля в одном буте (K=16 дважды) | восьмистрочные поля побитово идентичны |

При K=128 восемь будущих — читаемые инженерные рассуждения о задаче (все сходятся к мьютексу и двум
условным переменным для очереди MPMC; одна ветвь пропускает блок рассуждений и сразу начинает код).
При K=1500 каждая строка при температуре 1.0 накапливает артефакты «кракозябр» (фрагменты
кириллицы/арабского/CJK из хвоста словаря), тогда как жадная строка остаётся чистой.
Зафиксированная траектория Loop на 768 токенов — непрерывные инженерные рассуждения: кольцевой
буфер с двумя условными переменными, повторный пересмотр неоднозначности «опустошить или сразу
отказать» для close() между итерациями и анализ потерянного пробуждения через предикат. Текущий
фильтр пропустил 3 артефактных токена на 768 зафиксированных (~0.4%).

## 4. Ремонты, сделанные для достижения этой возможности

- **Идентичность поля (сервер)**: сид Gumbel головы AMD смещался счётчиком вызовов за бут, поэтому
  повторно используемый сервер давал разные поля для одинаковых запросов. Исправлено сбросом
  счётчика на REGION_FORK/REGION_RESET; подтверждено гейтом одного бута выше.
- **Накопление Loop (клиент)**: порционный рендер пишет строки с шагом, равным размеру порции, а
  выборщик читает с шагом K. Исправлено временным буфером на порцию с копированием в траекторию с
  шагом K. Границы порций — только точки наблюдения; выборщик видит те же K токенов, что и при
  одноразовом вызове.
- **Тупик выборщика**: когда каждая строка несла артефакт, первый выборщик исключал все строки и не
  фиксировал ничего. Текущий выборщик выбирает всегда: меньше артефактов — приоритет, ранний конец
  — сильный штраф, расстояние до консенсуса — второй приоритет.

## 5. Известные ограничения

- Регионный канал передаёт id токенов, а не логиты: построчных лог-вероятностей нет, поэтому
  взвешенное интегрирование Монте-Карло требует расширения логитов.
- Фильтр артефактов — пороговый дискриминатор по id на хосте, а не классификатор с токенизатором;
  ниже id 110000 есть ложноотрицательные.
- Полнословарный Gumbel при температуре 1.0 загрязняет длинные горизонты; ограниченный сэмплер
  (top-p/top-k) или более низкая температура — записанный следующий механизм.
- M=8 — проверенная ширина форка; путь состояния M=16 требует отдельного раунда корректности.
- QF_HEAD_TEMP и QF_HEAD_SEED читаются один раз при старте сервера: один сид на бут.
- Измерено на узле Spark с потолком мощности ~220 Вт и известной историей нестабильности (режим
  дефицита трансмиссии); запланирована замена на Atlas 300I, который ожидается лучше подходящим
  для этой нагрузки. Тайминги следует считать специфичными для узла.

## 6. Замороженные артефакты

FREEZE_OCHO_20260907 (поведенческие свидетельства: Beam K=128 и K=1500, гейт паритета,
воспроизведение утечки идентичности поля) и FREEZE_OCHO_CAPABILITY_20260907 (работающий Loop:
бинарники, исходники, гейт-журналы, прогон из 16 итераций и зафиксированная траектория). Оба
проверены SHA256 и отзеркалированы. Клиент Loop живёт в ветке stoch-engine-0907 (коммит 257a2a1);
сервер AMD с операцией коммита собран из архивного pre-B3 дерева форка плюс операция
QFW_REGION_COMMIT и сброс идентичности поля.
