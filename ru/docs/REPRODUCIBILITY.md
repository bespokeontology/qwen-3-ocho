# Воспроизводимость

## Авторитет

Канонический фриз-пакет FREEZE_QWEN_OVERNIGHT_20260907 (внутренние SHA256SUMS, зеркалирован на
трёх машинах) — авторитет для каждого числа в этом дереве. Публичные чеки — санитизированные
копии (хосты/пути заменены); оригиналы чеков — в пакете. См. freeze/PROVENANCE.md и
freeze/MANIFEST.md.

## Проверка

    ./scripts/verify_freeze.sh

проверяет публичные артефакты по SHA256SUMS публичного дерева и печатает класс происхождения
каждого компонента. Манифест приватного пакета дословно сохранён в freeze/package_SHA256SUMS
для перекрёстной проверки самого пакета.

## Автономное воспроизведение (любой CUDA GPU ≥ sm_70)

    ./scripts/reproduce_spark_tests.sh         # юнит-тесты ГПСЧ + Думитреску
    ./scripts/reproduce_mc.sh                  # MC-A / MC-A2 / MC-A3 / MC-B
    ./scripts/reproduce_stochastic_field.sh    # синтетическое поле + артефакт плотности

Требования: CUDA ≥ 12 (nvcc); для этих целей нет внешних зависимостей кроме CUDA toolkit.
Сохранённые сборки нацелены на sm_121a; скрипты уважают CUDA_HOME и QF_ARCH. Ожидаемые
выводы указаны в шапках скриптов и должны лежать в допусках чеков.

## Воспроизведение на стенде (две машины, замороженные бинарники)

Эксперименты на модели и чеки декодирования требуют двухмашинного стенда с замороженными
бинарниками, которых нет в этом дереве. Точное окружение и рецепты процитированы в чеках
(санитизированных) и в каноническом фриз-пакете. Ключевая конфигурация: продуктовый разрез
QF_LAYER_BEGIN=16, QF_AMD_PREFIX=16, QF_MAX_CONTEXT=16384, QF_EXPERT_MODE=full,
зафиксированные частоты; топология форка QF_LAYER_BEGIN=8, QF_AMD_PREFIX=8, QF_M1_INT8_HEAD=0.
Идентичность чекпоинта: RadixArk-Qwen3.8-Flash-Next-NVFP4 (раскладка каталогов — по
фриз-пакету). Замороженный продуктовый бинарник AMD — 824e5c50…; его точное дерево исходников
не восстановлено (PENDING-PROVENANCE), поэтому пересборка стороны AMD из исходников сейчас
невоспроизводима.

## Единицы

выборок/с, шагов-траекторий/с, завершённых траекторий/с и токенов-сиблингов/с — разные
величины и везде помечены. мс/токен и tok/s взаимно обратны только внутри одной конфигурации;
смешивать числа разных загрузок/конфигураций в одном сравнении без меток запрещено.
