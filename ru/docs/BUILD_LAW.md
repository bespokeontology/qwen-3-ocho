# Закон сборки

Рабочая дисциплина проекта, применённая к каждому механизму этого дерева.

## Один механизм за раунд

Заморозить предшественника. Изменить один физический механизм. Строгая сборка. Минимальный
гейт корректности. Сквозной чек. Затем распоряжение:

- материально хуже -> ROLLBACK;
- эквивалентно, но структурно лучше -> KEEP/PROMOTE (без заявления об ускорении);
- материально лучше -> KEEP с чеком производительности.

Ничья больше не уничтожает структурно лучшую работу; эквивалентность решается по структуре и
отсутствию регрессий, а ускорения заявляются только из измерений, которые их устанавливают.

## Правила чеков

- Искать существующие чеки до любых измерений.
- Один измеренный дискриминатор на точном замороженном рецепте до сборки.
- Числовые гейты задаются до эксперимента, а не после.
- Никогда не вычитать оценки из оценок.
- Чеки с выводами вставляют полный промпт и ответ.

## Замороженные линии

Префилл (1 543 tok/s), доливка и чек форка заморожены; они меняются только ради регрессии
корректности. M=8 — валидированная стохастическая ширина; у M>8 свой раунд корректности.
Продуктовый бинарник AMD заморожен до восстановления исходников.

## Дисциплина окружения

- Без Python в рантайме (только офлайн-инструменты). Пути обслуживания — CUDA/HIP C++.
- После любого профилировщика, до доверия чеку, фиксация частот применяется заново.
- Убивать по PID; никогда не убивать серверные процессы по шаблону (документированный режим
  отказа).
- Фриз-архивы обязаны нести полные деревья исходников, а не только бинарники (так были
  потеряны продуктовые исходники AMD).

## Авторитет вывода

Единственный авторитет по качеству вывода — оператор. Агенты измеряют, гейтят и докладывают;
они не судят связность или качество самостоятельно.
