# Qwen 3.ocho (C++) —— 原生 CUDA/HIP/ROCm 推理引擎（NVIDIA GB10 + 4x AMD MI50）上的随机轨迹渲染与决策/提交循环

本设备的原生 M=1 解码：8K 生产配方、无投机解码条件下实测 27–29 tok/s（冻结二进制回执，见第 4 节）。
Qwen 3.ocho 的随机模式与该路径并行存在；其逐行渲染成本单独列出，并非原生路径的替代。

一套双加速器、常驻状态推理与随机计算设备，围绕 Qwen3.8-Flash-Next 类模型构建。一台机器搭载
4x MI50（gfx906）AMD 层级，另一台搭载 NVIDIA GB10 层级。AMD 层级负责模型前缀、PLE 层与输出
头；NVIDIA 层级负责模型尾部。任何单块加速器都不持有完整模型。

本仓库是 2026-09-07 夜间窗口的工程记录：随机计算通道（新工作）与生产解码通道（一处正确性修复
与一处保留的选择器改动）。它是从规范冻结包（`FREEZE_QWEN_OVERNIGHT_20260907/`，内含
SHA256SUMS）派生的候选发布版本；冻结包是唯一权威。权威层级与各组件的来源标签见
`freeze/PROVENANCE.md`。

## 1. 本仓库是什么

一台原生（非投机）模型执行设备，基于 CUDA（NVIDIA GB10，sm_121a）与 HIP/ROCm（4x AMD MI50，gfx906），以及一个 GPU 原生随机评估引擎：后者把模型的常驻因果
状态视为受条件约束的转移算子。引擎把一个常驻父状态分叉为一片独立的随机分支场，在 GPU 上推进
它们，剪枝并压缩，评估观测量，并把整个场归约为统计量——无需把每条轨迹导出到 CPU。

两个子系统相连：为生产请求服务的常驻状态机制（预填充、再填充、续写），正是随机通道所分叉的
同一套机制。

## 5. Qwen 3.ocho —— 随机轨迹渲染与决策/提交循环

随机车道的模型支撑产品层。一份常驻父状态在两侧加速器上分叉为八条逐行延续；第 0 行保持贪婪，
第 1–7 行按确定性逐行 Gumbel-max 噪声采样（种子参数化）。八行经 M 行区域路径（AMD 前缀 ->
Spark 尾部 -> AMD 头部）同步推进。

- **Ocho Beam**：八条未来即输出。K=16 字段：5.16 s，24.8 sibling-tok/s。K=1500 Beam（C++/Rust
  任务）：各约 850 s、约 14 sibling-tok/s；长视野下温度 1.0 行累积尾部词表伪影，贪婪行保持干净。
- **分支记忆（概念验证）**：落选分支每轮贡献一条分类命题（约束/失败/未决问题），以有界的
  [OCHO BRANCH MEMORY] 块经常驻再填充路径注入已提交的冠军；落选 KV 绝不合并。
- **Ocho Loop**：渲染 -> 评估 -> 选择 -> 提交 -> 继续。评估简单且全程留痕（早停与伪影 token
  罚项，然后是循环状态签名上的共识距离）。所选行的完整状态在两侧提交回父槽位。能力运行：
  K=48 x 16 轮 = 768 个提交 token 的连续设计推理，每轮约 24 s，干净退出；同进程字段同一性门
  逐位一致。

Rust DAG 调度任务上的第二份能力轨迹（FREEZE_OCHO_RUST_LOOP_20260907）以同样的 16 轮结构运行，
选择器在六行间切换。受限候选采样器（收据 SAMPLER_TOPK_RECEIPT_20260907）已保留：311.9 ms/步
（全词表时为 324.6），第 0 行全词表 argmax 逐位一致，实测的尾部词表文本污染被消除。

完整机制、实测行为、修复与局限：docs/QWEN_3_OCHO.md。冻结能力产物：FREEZE_OCHO_20260907、
FREEZE_OCHO_CAPABILITY_20260907、FREEZE_OCHO_RUST_LOOP_20260907、FREEZE_OCHO_TOPKSAMPLER_20260907
（规范冻结包树；已 SHA256 校验）。

## 6. 随机计算引擎

```
  常驻受条件状态
        |
  GPU 原生分叉
        |
  确定性计数器 RNG（seed, branch, step, lane）
        |
  Kolmogorov 场推进（分支局部状态，共享不可变历史）
        |
  分支生存 / 剪枝 / 压缩
        |
  观测量求值
        |
  Dumitrescu 归约（N、Σw、Σw²、Σw f、Σw f²、log-sum-exp、ESS）
        |
  期望 / 积分 / 分布 / 渲染场
        |
  小结果返回主机
```

关键的区分在于：一个昂贵的常驻因果状态成为一片 GPU 常驻随机场的初始条件，其轨迹在 GPU 上
求值与归约。CPU 从不逐分支迭代。组件（全部有回执；见 `receipts/` 与
`docs/STOCHASTIC_ENGINE.md`）：

- **RNG** — Philox4x32-10，计数器式，按项目冻结的 RNG 规范实现（key=(slot,round)；
  counter=(position,branch,purpose,index)）。主机与设备两侧均通过已知答案测试。
- **Dumitrescu 归约** — 项目对其加权场归约原语的命名。fp64 累加、按块部分和、确定性主机合并、
  每分支多观测量、零权哨兵。14 个用例对照 CPU fp64 参考验证。
- **Kolmogorov 场推进** — 受条件父状态分叉为 M 个分支；分支局部可变状态加共享不可变历史；逐步
  击杀硬币剪枝并带权重补偿（无偏）；排他扫描压缩；观测量融合累加。合成实验中三个有闭式解的
  观测量全部吻合。
- **动态分支生存** — 剪枝与压缩每步执行；死亡分支贡献零权重并被移除。

吞吐：合成场在 GB10 上、M ≥ 262,144 分支时持续约 1.6e9 轨迹步/秒（约 16K 分支以下受发射
限制）。见 `receipts/THROUGHPUT_LAW_RECEIPT_20260907.md`。

## 7. 蒙特卡洛积分

引擎以具有闭式解的积分做验证；采样、被积函数求值与归约全部在 GPU 上：

| 门 | 解析值 | N | 估计 | 绝对误差 | 用时 | 样本/s | 备注 |
|---|---|---|---|---|---|---|---|
| MC-A：E[X²]，X~U(0,1) | 1/3 | 1,048,576 | 0.333675 | 3.4e-4 | 1.9 ms | 5.4e8 | 无权 |
| MC-A2：经 q(x)=2x | 1/3 | 1,048,576 | 0.333907 | 5.7e-4 | 2.1 ms | 5.0e8 | 加权，ESS 3.1e5 |
| MC-B：E[Σ X_j²]，d=16 | 16/3 | 262,144 | 5.334713 | 1.4e-3 | 0.65 ms | 4.1e8 | 向量 RNG |
| MC-A3：分层 S=64 | 1/3 | 1,048,576 | 0.333335 | 1.8e-6 | 1.8 ms | 5.8e8 | 等时下误差降约 188 倍 |

分层结果是保留的方差缩减机制：在对比的墙钟时间下绝对误差降低约 188 倍，而不是“蒙特卡洛快
188 倍”。对这类系统，有用的指标是每秒统计工作量（固定墙钟下的误差、ESS、轨迹/s），而非单纯
的样本/s。见 `docs/MONTE_CARLO.md` 与 `figures/variance_reduction.svg`。

## 8. 随机渲染

这里的“渲染”指可视化受条件随机过程生成的统计结构，而非传统光栅图形。合成场的末端状态对
（X_T, X_{T-1}）在 GPU 上分箱为 512x512 密度热图——采样、演化、观测量与归约全部在 GPU 侧。
保留工件：`figures/kolmo_field_density.ppm`（及无损 PNG 转换）。

图注：M = 1,048,576 分支；T = 64 步；OU 动力学 a=0.50、σ=1.00，父状态 x0=1.00；Philox4x32-10
（seed 42）；逐步击杀硬币 p=0.01 并带权重补偿 1/(1-p)；观测量 = 末端位置对；512x512 分箱，
[-3,3]²；推进用时 44.7 ms；约 1.5e9 轨迹步/秒；ESS = 550,847。见
`docs/STOCHASTIC_ENGINE.md` 的“渲染”一节。

## 9. AMD 层级

gfx906 层级是一等计算参与者。它持有每个生产 token 的前缀、PLE 与融合输出头；它剩余的毫秒数
是解码路径上实测最大的杠杆。其价值来自任务分解，而非孤立的设备基准：在常规单
设备对比中落后的硬件，只要架构按其物理特性（常驻层的 HBM 带宽/容量、自研 HIP 内核、状态持有）
分配工作，就能有实质用途。AMD 侧测得的长上下文税（8K 下约 2.4-2.8 ms/token）是当前最大的
单一可测杠杆。关于该税的两个假设已被对照实验否定（HIP 图：早期冻结；选择器二分：本窗口）。
剩余的可测位置是 QSA 打分内核与 flash attention 的增长。见 `docs/AMD_HETEROGENEOUS.md`
与 `figures/latency_breakdown.svg`。

## 10. 正确性方法论

不普遍要求位相同；每个机制有自己的门。本工作使用：语义必须精确处的 token 同一性；蒙特卡洛
内核的解析期望；RNG 的已知答案测试；归约的 CPU 参考；确定性种子重放；分支独立性；状态签名
比较；因果等价续写；compute-sanitizer memcheck；哈希来源。改动一次只做一个机制：严格构建、
最小物理门、端到端回执，然后 KEEP / ROLLBACK / PROMOTE。见 `docs/CORRECTNESS.md` 与
`docs/BUILD_LAW.md`。

## 12. 已知局限

- 生成冻结生产 AMD 二进制（824e5c50…）的精确源码树 **尚未找回**。用现有镜像重建（带或不带
  基数选择器）都在 token 0 处与冻结二进制发散；选择器移植本身已通过单元验证并保留为可应用，
  但在找回真实源码树之前不能取得生产集成回执。见 `freeze/PROVENANCE.md` 与
  `docs/LIMITATIONS.md`。
- M>8 随机宽度未验证：M=16 时第二槽状态签名量纲异常，且槽 0 相对 M=8 运行漂移。M=8 仍是
  已验证宽度。
- 区域协议只传 token id，不传逐行对数概率；加权模型蒙特卡洛需要协议扩展。
- 模型采样器扫描全词表（M=8 时约 110 ms/步）；受限候选集采样器是下一机制。
- Qwen 3.ocho 的伪影过滤器是主机侧 id 阈值判别器，在 id 110000 以下存在漏报；见
  `docs/QWEN_3_OCHO.md`。
