# 构建法

本项目的工程纪律，适用于本树中的每个机制。

## 每轮一个机制

冻结前任。改动一个物理机制。严格构建。最小正确性门。端到端回执。然后处置：

- 实质变差 -> ROLLBACK（回滚）；
- 等价但结构更优 -> KEEP/PROMOTE（保留/提升，不主张加速）；
- 实质变好 -> KEEP（保留）并附性能回执。

平局不再摧毁结构上更好的工作；等价由结构与无回归决定，加速只由能确立它的测量来主张。

## 回执规则

- 测量任何东西之前先检索已有回执。
- 构建之前，在精确的冻结配方上做一次测量判别。
- 数值门在实验之前设定，而非事后。
- 绝不用估计减估计。
- 涉及输出的回执粘贴完整提示与回答。

## 冻结通道

预填充（1,543 tok/s）、再填充与分叉证明均已冻结；仅为正确性回归而改动。M=8 是已验证的随机
宽度；M>8 有独立的正确性轮次。AMD 生产二进制在源码找回之前保持冻结。

## 环境纪律

- 运行时无 Python（仅离线工具）。服务路径为 CUDA/HIP C++。
- 任何剖析运行之后、信任回执之前，必须重新施加时钟锁定。
- 按 PID 杀进程；绝不用模式匹配杀服务进程（有记录的失败模式）。
- 冻结档案必须携带完整源码树，而非仅有二进制（AMD 生产源码正是这样丢失的）。

## 输出权威

输出质量的唯一权威是操作者。智能体测量、设门、报告；不自行判断连贯性或质量。
