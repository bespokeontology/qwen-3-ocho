# Qwen3.8-Flash-Next 异构引擎：原生推理与常驻状态随机计算

**版本：** 0.1.0-rc1 —— 候选发布版，未经同行评审，未公开推送。
**日期：** 2026-09-07。**权威：** 规范冻结包 FREEZE_QWEN_OVERNIGHT_20260907 及其回执；
见 freeze/PROVENANCE.md。

## 摘要

本文档记录一套双加速器原生推理设备——四块 MI50（gfx906）持有模型前缀、PLE 与输出头，一块
NVIDIA GB10 持有尾部——以及建立在该设备常驻状态之上的 GPU 原生随机计算引擎。随机引擎把
一个受条件的常驻模型状态视为一片独立分支场的初始条件：状态被分叉，分支在确定性计数器 RNG
下推进，死亡分支被剪枝与压缩，观测量被累加，整个场在 GPU 上归约为统计量。归约原语对照 CPU
参考验证；积分路径对照有闭式解的积分验证；分层采样在相同墙钟时间下把估计量误差降低约 188
倍；合成受条件场吻合三个解析期望，并持续约 1.6e9 轨迹步/秒；模型支撑场（常驻父状态八分支，
七随机一贪婪对照）在不导出轨迹的前提下产出场级统计。推理侧：8,038-token 上下文测得 29.70
原生 tok/s 权威基线；一处正确性修复与一处精确选择器替换被保留；30 tok/s 目标未达成（保留状态
29.44 tok/s），剩余的可测杠杆——AMD 长上下文税——受制于冻结生产 AMD 二进制的精确源码树尚未
找回。负面结果与来源局限均明确报告。

## 1. 动机

两个问题驱动本工作。其一：带常驻因果状态的自回归模型能否作为更大随机计算内部的昂贵受条件
转移算子——分支、求值、归约轨迹，而无需把每条轨迹导出到 CPU？其二：在常规单设备推理对比中
已过时的硬件，能否在围绕它分解的架构中保持实质用途？设备与随机引擎是对这两个问题的两个
回答，建立在同一套常驻状态之上。

## 3. 异构分解

模型在层边界（QF_LAYER_BEGIN）切分。每个解码步：AMD 前缀推进，残差经网络，Spark 尾部
（稠密 FP8 投影、路由专家、超连接、GDN 循环、QSA 稀疏注意力），残差返回，AMD 融合输出头加
下一前缀准备。AMD 层级每个 token 两次处于关键路径。图 1（figures/heterogeneous_pipeline.svg）。
分配遵循物理特性：常驻层与状态放在 AMD 层级，尾部计算放在 GB10。切分不是基准工件，而是服务
配置。

## 4. 常驻因果状态

两个层级保持一切常驻：权重、KV、GDN 循环状态、卷积环、QSA 索引池、专家槽位映射。再填充
无重放注入新上下文；续写恢复任意常驻状态；分叉把一个已灌注父状态复制到两个层级各 M 个行槽。
常驻状态是随机覆盖层可行的前提：分叉是状态复制（毫秒级），不是重算。

## 6. GPU 原生随机场抽象

核心架构观察：带常驻因果状态的自回归模型可以视为更大随机计算内部的昂贵受条件转移算子。
流水线（图 2，figures/stochastic_pipeline.svg）：

    常驻受条件状态 -> GPU 分叉 -> 确定性计数器 RNG -> 场推进
    -> 生存/压缩 -> 观测量求值 -> 归约 -> 小结果返回主机

区分性不在“能生成多个续写”，而在：一个昂贵的常驻状态成为一片 GPU 常驻场的初始条件，其轨迹
在 GPU 上求值与归约，无需逐轨迹导出到 CPU。两个原语在概念上分离：Kolmogorov 推进（演化受
条件场）与 Dumitrescu 归约（求值与归约）。分离在核融合之后依然成立；生成与估计是不同关注点。

分支状态小而分类明确：逐分支可变追加状态（KV 行、索引池）、必复制状态（GDN、卷积环、PLE）与
廉价元数据（位置、token、对数权重、观测量累加器、存活标志）。共享不可变历史从不被子分支改写
（分叉独立性回执证明）。RNG 状态不存储：流以 (seed, branch, step, lane) 计数器寻址。每分支
描述符 16 B，100 万分支初始化 0.08 ms，此规模无需写时复制。见 stoch/BRANCH_DESCRIPTOR.md。

分支身份因此完全由（父状态、种子、分支槽、步）决定：分叉复制小的可变状态，轨迹可仅凭计数器
复现。压缩改变槽编号，但因步号是每个 RNG 地址的一部分，后续步复用的槽不会与已抽取的流冲突；
确定性按构造在压缩后依然成立。对数权重字段兼作终止标记（lw <= -1e300 表示死亡），于是剪枝、
加权与归约共享同一表示。

## 7. 确定性 RNG

Philox4x32-10，按项目冻结 RNG 规范实现（key=(slot,round)；
counter=(position,branch,purpose,index)；uniform=(word0>>8)*2^-24）。已知答案测试
（counter=key=0 -> 6627e8d5 e169c58d bc57ac4c 9b00dbd8）在主机与设备通过；确定性、流独立性
（2,048 单元，无别名）、计数器快照/恢复与 100 万均匀样本均值/方差检查全部通过。计数器式寻址
正是分叉、重放与分支身份廉价的原因：没有需要复制或恢复的 RNG 状态。

## 8. Kolmogorov 场推进

合成场在一个可解析检验的过程中锻炼每个机制。父状态 x0=1.0 分叉为 M 个 Ornstein-Uhlenbeck
动力学分支（a=0.50、sigma=1.00），噪声为计数器 RNG 的 Box-Muller。每步：推进、击杀硬币
（p=0.01）以权重补偿 1/(1-p)（无偏俄罗斯轮盘）、排他扫描压缩、观测量融合累加。三个闭式门：
E[X_T] = a^T x0；E[X_T²] = (a^T x0)² + sigma²(1-a^{2T})/(1-a²)；E[(1/T) Σ x_t²]。三者均在
期望蒙特卡洛误差内吻合；生存率（52.5%）与击杀硬币预测（0.99^64 = 52.6%）一致；ESS 等于
幸存者数（等权）。吞吐从 M=1,024 的 2.6e7 轨迹步/秒增至 M=1,048,576 的 1.60e9，约 262K
分支以上饱和（约 16K 以下受发射限制）。

剪枝规则是场的第一个加权机制，值得精确陈述。在步 t 幸存的分支，其对数权重减 log(1-p)；在
步 t 被击杀的分支被移除。对步 t 累加的观测量，E[w_t · f_t · 1_alive(t)] = E[f_t] ·
(1-p)^t · (1-p)^(-t) = E[f_t]，因为击杀硬币与过程独立：权重恰好补偿删除，于是幸存者上的
加权均值估计未剪枝期望。加权模型蒙特卡洛将使用同一结构，只是把击杀硬币补偿换成分支的
条件对数概率。

## 9. Dumitrescu 统计归约

归约原语单遍计算 N、Σw、Σw²、Σw f_k、Σw f_k²、max log-w、log-sum-exp(log w) 与 ESS，
每分支 K 个观测量：fp64 累加、按块部分和、确定性主机合并（无跨块原子操作）、零权哨兵。
14 个用例对照 CPU fp64 参考验证（奇数规模、30% 死亡、权重 1e-30..1e30、全零、K=1/2/4、
带符号观测量），和与矩分别在 1e-12 与 1e-9 内。该原语是场的统计边界：跨回 CPU 的是少数合并
标量，而非分支值。

## 10. 蒙特卡洛积分验证

| 门 | 解析值 | N | 估计 | 绝对误差 | 用时 | 样本/s | 备注 |
|---|---|---|---|---|---|---|---|
| MC-A：E[X²]，X~U(0,1) | 1/3 | 1,048,576 | 0.333674980 | 3.4e-4 | 1.9 ms | 5.4e8 | 无权；1-sigma 约 2.9e-4 |
| MC-A2：经 q(x)=2x | 1/3 | 1,048,576 | 0.333907284 | 5.7e-4 | 2.1 ms | 5.0e8 | 加权；ESS 约 3.1e5 |

物化。场引擎使用的正是同一套累加结构，因此这些门验证了场依赖的归约边界。

## 11. 方差缩减

分层（抖动）采样，S=64 层：u = (层号 + uniform)/64。相同 N，相同用时（1.8 对 1.9 ms）：
普通 MC-A 误差 3.4e-4；分层误差 1.8e-6——对比墙钟时间下绝对误差低约 188 倍（图 6，
figures/variance_reduction.svg）。教训在指标而非机制：对蒙特卡洛系统，优化目标是每秒统计
工作量——固定墙钟下的估计量误差、ESS、轨迹/s——而非单纯样本/s。采样规则改动在这里零成本，
换来两个数量级的精度。

## 12. 随机渲染

渲染定义为可视化受条件随机过程生成的统计结构，而非光栅图形。合成场的末端对（X_T,
X_{T-1}）在 GPU 上分箱为 512x512 密度网格并写为 PPM（figures/kolmo_field_density.ppm 及
无损 PNG 转换）。参数：M=1,048,576；T=64；a=0.50、sigma=1.00；x0=1.00；Philox seed 42；
p_kill=0.01 带权重补偿；推进用时 44.7 ms；约 1.5e9 轨迹步/秒；ESS 550,847。工件演示通用
链条——随机样本 -> 场演化 -> 观测量 -> 归约/渲染——作为一等机制而非图形演示。

## 13. 模型支撑的受条件随机求值（MC-C）

桥梁实验：一个常驻父状态（382 token，8/40 切分，冻结分叉二进制）分叉为 M=8 行。第 0 行是
贪婪对照；第 1-7 行按温度 1 的 Gumbel-max 采样转移（服务端采样器，确定性 splitmix64，以
(seed,row,v) 为键）。16 步后，读回逐行状态签名（sigR：Spark 各层 GDN+卷积状态之和；sigK：
最近 4 个位置 K/V 之和），在 7 个采样行上无权归约：场均值 sigR +228 vs 贪婪行 sigR -704
（样本标准差 1076，ESS 7）；末端 token 分布 318 x3、264、19、8260、53235、156566；执行
367.5 ms/步（21.8 兄弟 token/s；全词表 Gumbel 循环约 110 ms/步）。重复运行按位复现 token
轨迹（签名值在记录的 M 行算术带内波动——各行从位相同的分叉状态与相同 token 出发，但 M 行
体内的浮点算术跨运行不位稳定；token 同一性是项目的门，且它成立）。意义在架构：同一场机制
作用于真实常驻模型状态，而非仅合成过程。此处的归约刻意平凡——七个采样分支上的无权均值——
因为区域协议只传 token id，不传逐行对数概率；一旦协议携带被采样 token 的条件概率，同一场就
归约为模型受条件期望的恰当加权蒙特卡洛估计，并免费获得 ESS 报告。不做超出此处的声明：这不
演示通用贝叶斯推理或世界模型模拟。

## 14. 旧 AMD 硬件为何重要

仓库 README 第 9 节与 docs/AMD_HETEROGENEOUS.md 载有完整论证；要点：四块 gfx906 设备持有
每个生产 token 的前缀、PLE 与输出头，其剩余长上下文税是设备与 30 tok/s 目标之间的最大可测

毫秒从哪里来。声明刻意收窄：异构分解让在常规单设备对比中过时的硬件，在现代服务与随机计算
系统中具有实质用途。

## 16. 正确性方法论

位相同并非普遍要求；每个机制有自己的门：语义必须精确处的 token 同一性（B1、B2）；蒙特卡洛
内核的解析期望；RNG 的已知答案；归约的 CPU 参考；确定性种子重放；分支独立性；状态签名；
因果等价续写；compute-sanitizer memcheck；哈希来源。工作纪律是一次一个机制——严格构建、
最小物理门、端到端回执，然后 KEEP / ROLLBACK / PROMOTE——输出质量的唯一权威是操作者。
具体案例：B1 以急切 vs 图捕获的 token 同一性设门（修复前在第 92 个 token 漂移，修复后
300/300 一致）；B2 以 13 用例单元测试加 memcheck 加 300/300 token 一致回执设门；RNG 以已知
答案测试；归约以 CPU 参考。见 docs/CORRECTNESS.md 与 docs/BUILD_LAW.md。

## 17. 生产通道机制

**B1 — 图捕获冻结的打分域（正确性）。** QSA 索引器以 nfull_max = (pos0_host + T) >> 2 从
主机位置确定打分 GEMM、平面缓冲与折叠的规模。在捕获的解码图（T=1）内该值在捕获时冻结：
生成期间新建的块从未被打分，top-2048 选择静默忽略最新上下文。判别器：急切解码（逐步重算
边界）vs 捕获图。修复前二进制在第 92 个 token 漂移（97/300 一致）；修复后二进制（T=1 时
GEMM 按分配上限取值）急切与图捕获 300/300 token 一致。代价：GEMM 维度翻倍，约
+0.5 ms/token。

**B2 — 精确单遍 top-512 选择。** 48 步阈值二分被替换为对保序 uint32 浮点键的 4 遍基数选择，
平局语义完全一致（掩码 sc > t，按块序升序填充 t 处的平局，全非正退化情况选择 {sc > 0} 且
不填充）。验证：13 用例单元测试对照原二分的宿主实现加 memcheck（0 错误）；随后 300/300
token 一致生产回执与尾部 23.5 -> 23.1 ms/token。不主张大的端到端加速；收益是约 0.4 ms/token
的尾部与 48 步依赖的移除。

**B3 — AMD 孪生移植（移植已验证，集成受阻）。** 同一基数构造移植到 AMD top-k 内核并在
gfx906 上单元验证（10/10 非稠密用例精确）。集成被尝试并拒绝：每次重建（带与不带基数选择器）
都在 token 0 处与冻结生产二进制发散，因为冻结二进制的真实源码树未找回，而现有镜像仅部分
哈希核验。移植保留为实验性、已单元验证、待集成。

## 18. 负面结果

- **30 tok/s 未达成。** 基线 29.70；保留 29.44。目标未达成，且不四舍五入。保留改动是正确性
  与精确性工作，不是加速机制；净效应在方差之内。
- **AMD 选择器假设被否定。** 受控重建中基数选择器与二分产生相同实测头部时间
  （10.8 ms/token）；2048 边界税位于 QSA 打分内核与 flash attention 的增长。
- **M>8 未验证。** M=16 时第二槽状态签名量纲异常，槽 0 相对 M=8 运行漂移。M=8 仍是已验证
  随机宽度；M=16 数字不作为有效随机扩展发布。
- **AMD 来源未决。** 冻结生产 AMD 二进制的精确源码缺失；任何镜像均不具权威性（第 19 节）。

## 19. 可复现性与源码来源

独立随机内核可在任意 CUDA GPU ≥ sm_70 上从 stoch/ 构建运行（scripts/reproduce_*.sh；保留
构建面向 sm_121a，脚本遵循 QF_ARCH）。生产通道改动是相对 m8-amd-routed @ 420bca8 的补丁，
该基座不在本树中。依赖模型的实验需要双机设备与冻结二进制。各组件来源标签见
freeze/PROVENANCE.md；AMD 生产源码为 PENDING-PROVENANCE，不为其主张源码可复现性。

## 20. 局限

- AMD 生产源码树未找回；AMD 工作冻结（见上）。
- 原生 30 tok/s 未达成；下一机制（AMD QSA 层降到字节下限）受来源所阻塞。
- M>8 随机宽度未验证。
- 区域协议只传 token id，不传逐行对数概率；加权模型蒙特卡洛需要协议扩展。
- 模型采样器扫描全词表（M=8 时约 110 ms/步）。
- MC-C 目前单种子（种子在服务端启动时读取）；双种子一致性需要重启服务端。
- sigR 无更宽泛统计解释；它是轨迹观测量。

## 21. 未来工程工作

按门就绪度排序：（1）找回并哈希匹配 824e5c50 的精确 AMD 源码树，然后集成已验证的基数选择器

## 22. 结论

一个常驻模型状态被变为一片 GPU 常驻随机场的初始条件：分叉，在确定性逐分支随机性下推进，
剪枝、压缩、观测、归约——积分路径对照闭式积分验证，归约路径对照 CPU 参考验证，并有一个
实测的方差缩减机制在相同墙钟下换取两个数量级的精度。同一设备在 8K 上下文测得 29.70 原生
tok/s，保留一处正确性修复与一处精确选择器替换，未达 30；差距与阻塞均已测量并陈述。工程
记录（含其失败）在回执之中。
