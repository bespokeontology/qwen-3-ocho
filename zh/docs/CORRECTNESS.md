# 正确性模型

本项目中位相同并非普遍要求。每个机制有自己的门，选择为能够抓住错误实现的最小物理检查。
保留工作中使用的门：

| 门 | 机制 | 所确立的性质 |
|---|---|---|
| 已知答案测试 | RNG | 生成器符合冻结规范（主机与设备两侧 KAT） |
| CPU 参考 | Dumitrescu 归约 | 归约统计量与 fp64 参考一致（14 用例，容差已注明） |
| 解析期望 | MC-A / MC-A2 / MC-B / 合成场 | 估计量与闭式解在期望蒙特卡洛误差内吻合 |
| token 同一性 | B1、B2 | 规则要求处语义完全等价（300/300） |
| 急切 vs 图捕获判别器 | B1 | 捕获图的冻结域与急切域一致 |
| 单元测试 vs 原算法 | B2、B3 | 替换精确复现二分（13 与 10 个用例） |
| compute-sanitizer memcheck | B2 开发、分叉诊断 | 无越界访问 |
| 确定性种子重放 | MC-C、RNG | 相同输入复现相同轨迹 |
| 分支独立性 | 分叉证明（更早冻结） | 强制 token 扰动只移动被扰动的行 |
| 状态签名 | MC-C | 轨迹观测量跟随分支（sigR 跟随 token） |
| 因果等价续写 | 再填充（更早冻结） | 恢复状态产生连贯续写 |
| 哈希来源 | 所有保留二进制 | 每个工件以 SHA256 与冻结记录寻址 |

顺序很重要：先跑廉价的单元门（分钟级），再跑端到端回执。本窗口内，单元门在任何回执之前就
抓住了 B2 选择器的三处缺陷（第 0 遍前缀掩码的未定义移位、阈值放在每线程寄存器而只有线程 0
推进它、丢失秩偏移），以及加权门的一处缺陷（均匀提取器作用于原始字而非 word>>8）和归约的一处
缺陷（共享内存行宽漏了三列）。端到端 token 门的存在，正是为了抓住单元测试会漏掉的那类缺陷；
两者都保留。

输出质量的唯一权威是操作者；智能体只测量与报告。
