# 局限

## AMD 源码来源（阻塞）

生成冻结生产 AMD 二进制（824e5c50…）的精确源码树尚未找回。现有镜像仅部分对照冻结记录做了
哈希核验。受控重建（带与不带基数选择器）都在 token 0 处与冻结二进制发散，因此选择器移植被
洗清嫌疑，而重建本身缺少来源。AMD 生产工作在源码考古找回并哈希匹配真实树之前保持冻结。
基数选择器移植保留为实验性、已单元验证、待集成（patches/amd_pending/）。

## 原生 30 tok/s 未达成

夜间权威基线：8,038-token 生产配方下 29.70 tok/s。B1+B2 之后的保留状态：29.44 tok/s
（净 +0.1 ms/token，处于方差之内）。剩余差距约 0.34 ms/token。下一机制（AMD QSA 层打分 +
注意力降到字节下限）受上述来源恢复所阻塞。

## M>8 随机宽度未验证

M=16 时第二槽状态签名量纲异常，且槽 0 相对 M=8 运行漂移。M=8 是已验证宽度；M=16 不作为
有效随机扩展发布，并有独立的正确性轮次。

## 模型蒙特卡洛的缺口

- 区域协议只传 token id；无逐行对数概率，因此加权模型蒙特卡洛需要协议扩展。
- 模型采样器扫描全词表（M=8 时约 110 ms/步）；受限候选集采样器是下一机制。
- MC-C 目前单种子：采样种子在服务端启动时读取，双种子一致性需要重启服务端。
- sigR/sigK 是分支状态的确定性泛函，用作轨迹观测量；不主张更宽泛的统计解释。

## 冻结二进制隐患（已记录，未修复）

分叉配方要求 QF_EXPERT_MODE=full。默认专家模式下，冻结二进制预填充路径在 T=256 块上发生
越界读（compute-sanitizer 证据见 B3 与 MC-C 回执）。历史上实际使用的配方不受影响；记录该
隐患是因为分叉回执省略了专家模式变量。

## 范围排除

投机解码/MTP、量化变更、HIP 图（被更早测量否定）以及任何 M=8 性能返工均不在范围内。本树
不对其他服务系统做比较声明；外部数字需要沿多个维度（原生 vs 投机、精度、上下文、硬件、
并发）标注，因此不予收录。
