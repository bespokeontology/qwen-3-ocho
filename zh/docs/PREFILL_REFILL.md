# 预填充与常驻再填充

这些机制在夜间随机工作之前已冻结；此处记录它们是因为它们界定了本设备中“常驻状态”的含义。
所有数字来自更早的规范冻结（FREEZE_QWEN_PREFILL_1543_20260906 与再填充回执）；本窗口未做
任何改动。

## 冻结预填充

生产异构预填充，8,038 token 提示，T=2048 逻辑块，AMD 前缀 + Spark 尾部：
**5.21 s ≈ 1,543 tok/s**（同二进制区间 5.21-5.42 s）。保留的推进过程，每个被接受的步骤对应
一次 8K 回执：

| 步骤 | 灌注用时 |
|---|---|
| 两个 AMD 块并行在途 | 6.02 s |
| 融合 HC/路由器胶水 | 5.78 s |
| 融合 GDN 后处理 | 5.70 s |
| AMD 联合瓦片 QSA | 5.44 s |
| 批量 CSR + 64-token 专家通道 | 5.26 s |
| 最终生产回执 | 5.21 s |

同二进制的更早回执：382 token 用时 0.85 s；2,038 token 用时 2.18 s；5,038 token 用时 4.35 s。
已知更差的变体（512-token 首块、折半尾块切分、8-warp 专家形式、顺序 GDN、手写 fp8 GEMM、
列表核注意力、逐位置 AMD QSA）保持默认关闭，并记录在冻结文档中。

## 常驻再填充 / 上下文注入

再填充把新增上下文注入常驻状态而不重放：注入区经预填充路径分块处理；出口状态续写恢复解码。
图生命周期规则适用：注入时使已捕获的尾部图失效并重新捕获（约 4 ms）。实测：136 token 用时
0.60 s（TTFT 0.65 s）；2,038 token 用时 2.19 s（1024 子块）；5,038 token 用时 4.06 s
（≈1,240 tok/s）；链式注入至 15.8K 常驻上下文；续写 26-28 tok/s；与冷启动 A/B 对照：前 41 个
token 一致，随后措辞分歧（已接受）。微小后缀准入下限约 0.6 s 已记录。

## 对随机通道的意义

常驻状态是随机引擎一切行为的前提：它可以被续写、无需重放地扩展、分叉为分支场、进一步施加
条件。每个场实验开头的分叉，都是这套机制所创建状态的复制；分叉回执（更早的冻结）确立了
一个父状态无需重放即可产生八个物理独立的因果子状态。
