# gfx906 在异构流水线中的角色

## AMD 层级实际持有的是什么

生产配置下，四张 MI50 持有模型 0..15 层、PLE 层与 lm_head。每个解码步两次穿过 AMD 层级：
Spark 尾部之前的前缀推进，以及之后的融合输出头（输出 HC + lm_head + argmax）加下一前缀窗口。
AMD 层级是关键路径两端的计算，带常驻专家 arena（生产为 INT8；分叉拓扑为 NVFP4+INT8）与
自己的 QSA 索引路径。它不是存储，也不是挂在流水线边上的设备。见
figures/heterogeneous_pipeline.svg。

## 实测贡献

8,038-token 生产配方下，AMD 融合头实测 10.7-10.8 ms/token，Spark 尾部 23.0-23.5 ms/token。
短上下文下头部为 8.2-8.6 ms；差值（2.4-2.8 ms/token）即 AMD 长上下文税。整步 33.7 ms，而
30 tok/s 的预算为 33.33 ms，因此 AMD 税是当前最大的单一可测杠杆——大致等于全部剩余差距再加
余量。

## 税不在哪里

关于 AMD 长上下文税的两个假设已由对照实验否定：

1. HIP 图 / 发射开销。更早的冻结测出暴露的主机残差 0.63 ms/token，并关闭了这条路线
   （AMD_M1_LAUNCH_OVERHEAD_DISCRIMINATOR 回执）。
2. 索引器的 48 步阈值二分。本窗口把精确基数选择器移植到 AMD top-k 内核，在 gfx906 上对照
   二分参考做了单元验证（10/10 非稠密用例精确），并分别以带与不带基数选择器重建了服务端。
   两次重建测得相同头部时间（10.8 ms/token）。因此选择器不是 2048 边界抬升的可测来源。
   剩余的可测位置是 QSA 打分内核与所选列表上 flash attention 的增长（8K 下每个 QSA 层约
   0.8 ms，短上下文约 0.46 ms）。

## 来源约束

生成冻结生产 AMD 二进制（824e5c50）的精确源码树尚未找回。用现有镜像重建（带或不带基数
选择器）都在 token 0 处与冻结二进制发散——移植由单元门与无基数对照洗清嫌疑，而重建本身缺少
生产源码来源。AMD 生产工作在找回真实源码树并做哈希匹配之前保持冻结。基数选择器移植保留为
实验性、已单元验证、待集成。见 freeze/PROVENANCE.md 与 docs/LIMITATIONS.md。

## AMD 侧为何仍然有价值

本系统中加速器的价值来自任务分解，而非赢得孤立的单设备基准。在常规对比中落后的设备，只要
架构按其物理特性分配工作，就仍能有实质用途：MI50 层级贡献常驻层的 HBM 容量与带宽，运行匹配
gfx906 的自研 HIP 内核，持有长生命周期状态，并把前缀与输出头移出另一层级的延迟预算。其测得
的弱点——长上下文 QSA 税、被否定的 HIP 图想法、被否定的选择器想法——被精确记录，因为它们
划定了下一批毫秒从哪里来。此处的声明是窄的：异构分解让在常规单设备推理对比中已过时的硬件，
在现代服务与随机计算系统中具有实质用途。不主张 MI50 在任何孤立对比中快于其他设备。
